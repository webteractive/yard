# Yard databases (`yard db`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Approved by the maintainer on 2026-11-15**, to run natively (superpowers:executing-plans) on main.

**Goal:** `yard db list|create|connect|open|shell|dump|import` for MySQL and PostgreSQL instances, and
`yard db connect` for what a GUI client needs, with the same in Yard.app's Services screen.

**Architecture:** yardd decides and the client moves the bytes. yardd's new `db.*` methods resolve
and wake the instance, run the small queries (`db.list`, `db.create`) with the instance's client
by keg path over its socket, and for shell, dump and import answer `db.command`: the exact program,
arguments and environment, after validating the name and the passed-through flags, picking the keg,
creating the database for an import and refusing one with tables. The CLI runs that command in the
user's terminal (macOS privacy rules would refuse yardd the user's folders), pumping the file
through `/usr/bin/gzip` and a pure `yard-core` statement filter. Yard.app runs the CLI.

**Tech Stack:** Rust 1.92 (tokio, serde, clap, insta), the engines' brew clients (`mysql`,
`mysqldump`, `psql`, `pg_dump`, `pg_restore`), `/usr/bin/gzip`, `/usr/bin/open`; GPUI for Yard.app.

**Spec:** `docs/superpowers/specs/2026-11-15-yard-db-design.md` (approved 2026-11-15). Read it
first; this plan argues from it, and section numbers below (§n) are the spec's.

## Global Constraints

- Protocol `2.12` (additive). New methods `db.list`, `db.create`, `db.connect`, `db.command`; they join `methods::ALL` and main spec §6.2.
- New error codes, SCREAMING_SNAKE on the wire: `DB_SERVICE_AMBIGUOUS`, `DB_NO_SERVICE`, `DB_UNSUPPORTED_ENGINE`, `DB_NOT_EMPTY`, `DB_FLAG_RESERVED`, `DB_DUMP_SWITCHES_DATABASE`, `DB_NO_HANDLER`, `DB_TOOL_FAILED`, `FILE_EXISTS`, `SERVICE_STOPPED`, `SERVICE_WAKE_TIMEOUT`. Every hint is the command that fixes it.
- Database names: `[A-Za-z0-9_-]`, 1–63 characters; quoted as identifiers in every statement (backticks on MySQL, double quotes on PostgreSQL).
- Yard never connects to a server that is not the named Yard instance, never drops a database, never creates users or roles, and never starts an instance with `stopped = true`.
- MySQL's tools come from the instance's keg; PostgreSQL's from the newest installed `postgresql@N` keg with N ≥ the instance's major (§7.1).
- Yard's runs of `mysql`/`mysqldump` start with `--no-defaults`; of `psql` with `--no-psqlrc`; PostgreSQL's dump and import clear `PGHOST PGHOSTADDR PGPORT PGUSER PGDATABASE PGPASSWORD PGPASSFILE PGSERVICE PGSERVICEFILE`. `shell` keeps the user's files.
- `psql` imports run with `-v ON_ERROR_STOP=1` before the user's arguments.
- Dump compression is `--compress`, off by default, gzip through `/usr/bin/gzip`; import gunzips any file starting `1f 8b` with `/usr/bin/gzip -dc`. No new crates in either workspace.
- Dumps write `<file>.partial` and rename on success; a failure or Ctrl-C deletes it.
- Wake waits up to 30 s, then `SERVICE_WAKE_TIMEOUT` (hint `yard service logs <instance>`).
- `yard-core` stays pure (no spawning, files or clock); `yard-client` stays yard-proto and tokio only; no `.unwrap()`/`.expect()` on daemon runtime paths.
- Tests never bind 3306, 5432, 6379, 9000, 9001, 80, 443, 8080, 8443, 53 or 53535 and never run real engines; daemon tests use `yard-fake-unit`, CLI tests `MockDaemon`.
- Work on main. Commit messages: lowercase prose subject, no type prefix, prose body, no trailers. Ask the maintainer before each commit unless he has approved the run.

### Decided while planning (the spec is amended in Task 12)

- **Yard.app runs the CLI** (`AppEnv::run_cli`) for dump and import, with `--progress-json` (Task 9), rather than linking the runner: the app rule already allows running `yard`, the runner then exists once, and the CLI child inherits the app's file access from the open or save panel. Spec §10's "the app runs dumps and imports itself" changes to this.
- **Argument order.** MySQL tools: Yard's flags, then the database name (`mysqldump`) or `--database=<name>` (`mysql`), then the user's arguments (MySQL's option parser reads options after the name, so `-- --routines` and a trailing table list both work; Task 3 checks this against the real keg before relying on it). PostgreSQL tools: Yard's flags including `-d <name>`, then the user's arguments, then a directory-format path last (macOS's getopt does not reorder, so nothing positional precedes an option).
- **Where things run:** `db.list` and `db.create` run `mysql -N -B -e` / `psql -At -c` from yardd; `db.command` runs nothing but its checks (the empty-database check is a query).

## Review Focus

1. **MySQL's executable comments** (`/*!40101 SET … */`, `/*!50001 CREATE … VIEW */`) are statement text that MySQL runs, not comments: the filter must look inside them, and a `/*!32312 USE shop*/` (what `mysqldump --databases` writes) is a switch (Task 4, `executable_comment_use_is_a_switch`).
2. **A single statement far bigger than a read buffer** (a 20 MB extended `INSERT`, a long `COPY` block) arrives across many chunks and leaves the filter byte-identical and in order (Tasks 4 and 5, `a_statement_split_across_chunks_passes_intact`).
3. **A missing, unreadable or empty import file** fails before `db.command` is called, so no database is created for nothing (Task 10, `a_missing_file_creates_nothing`).
4. **A hyphenated name** (`my-app`) is quoted wherever Yard writes SQL, and reaches the tools unquoted as an argument (Task 2, `hyphenated_names_are_quoted`; Task 7, `create_quotes_a_hyphenated_name`).
5. **Ctrl-C during a dump or import** stops the tool and gzip, leaves no `.partial`, exits 130, and says what an import left behind (Task 9, `ctrl_c_leaves_no_partial`; Task 10, `ctrl_c_says_what_stays`).

  - `filter::Filter` trait-free enum: `pub enum Filter { Pass, Mysql(MysqlFilter), Postgres(PostgresFilter) }` with `pub fn new(f: &StreamFilter) -> Filter`, `pub fn push(&mut self, chunk: &[u8]) -> Result<Vec<u8>, Switch>`, `pub fn finish(&mut self) -> Result<Vec<u8>, Switch>`, `pub fn skipped(&self) -> usize`.

  - `MysqlFilter` holds the bytes of the statement in progress and emits each complete statement unchanged, in order. It tracks `'…'`, `"…"`, `` `…` `` (with backslash and doubled-quote escapes), `-- ` and `#` line comments, `/* */` comments, `/*!NNNNN … */` executable comments (their text **is** statement text), and `DELIMITER x` lines (the client command; the delimiter changes until the next `DELIMITER`). A statement whose first keyword (after comments, and inside a leading executable comment) is `USE`, `CREATE DATABASE`/`CREATE SCHEMA` or `DROP DATABASE`/`DROP SCHEMA` is a `Switch`; nothing of it is emitted. (`DROP DATABASE` is not in spec §6.6's list, but `mysqldump --databases --add-drop-database` writes it ahead of the `CREATE`, and it would drop a database the import does not name; Task 12 adds it to the spec.)
