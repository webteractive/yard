# M6 Yard.app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** approved by the maintainer 2026-11-06 and built that day, inline on main (Tasks 1–17); the
rulings made while building are in the commit messages.

**Goal:** Yard.app, a Rust menu bar app and main window written with GPUI, a pure JSON-RPC client of
yardd, with live state from events, job progress, errors with fix actions, and onboarding.

**Architecture:** Six root-workspace tasks first: fallbacks on every enum a newer yardd may extend,
a `reconciled` event and `php.list { available }` (protocol 2.11), and a new `yard-client` crate
holding the CLI's client, a pipelined connection and a reconnecting session. Then a second Cargo
workspace in `app/` (Zed's Rust 1.98.1, its own lockfile and deny policy) with GPUI pinned by git
`rev` to Zed `v1.27.0`: `yard-app-model` (decisions, no GPUI, no I/O, tested with `cargo test`) and
`yard-app` (a tokio bridge, GPUI entities tested with `#[gpui::test]`, platform glue through
`objc2`, the menu bar through `tray-icon` and `muda`, widgets and screens).

**Tech Stack:** Rust 1.92 (root: yard-proto, yard-core, yard-client, yard-daemon, yard-cli; tokio,
serde_json, `time`, `plist`); Rust 1.98.1 (app: `gpui` and `gpui_platform` from
`https://github.com/zed-industries/zed` at `c84af5b99cbc366d675064e52b23664a015b6e35`, `tray-icon`
0.26, `muda` 0.21, `objc2` 0.6 with `objc2-foundation` and `objc2-app-kit` 0.3, tokio,
`futures`); Xcode 26.6 (macOS 26 SDK, Metal toolchain); a shell script for the bundle.

**Spec:** `docs/superpowers/specs/2026-11-05-yard-m6-app-design.md` (draft, not approved). Main
spec: `docs/superpowers/specs/2026-10-19-yard-design.md` (§3.1, §6, §9, §10, §12).

## Global Constraints

- Root workspace tasks (1–6): Rust 1.92; no new third-party crate (tokio, serde_json, `time` and
  `plist` are already in `Cargo.lock`; a new workspace crate is fine); `cargo fmt --check`, `cargo
  clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass after each.
  `yard-proto`, `yard-core` and `yard-client` must also compile on 1.98.1 (the app builds them).
- App workspace tasks (7–17): run cargo in `app/` (its `rust-toolchain.toml` picks 1.98.1); `cargo
  fmt --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings` and `cargo test
  --workspace --locked` pass after each; every new crate is vetted per the rust-dependencies rule,
  and `cargo deny check` passes in `app/` after any `app/Cargo.lock` change. Never take a crate
  from Zed outside GPUI's tree (`ui`, `theme`, `editor` are GPL); `gpui-component` is not used.
- `yard-app-model` imports no GPUI, no tokio, no `std::fs`, no `std::process`, and reads no clock
  (`now` is a parameter). Only `yard-app` imports `gpui`, `tray-icon`, `muda` or `objc2*`.
- The app never writes a file in Yard's data root or a project, never runs `brew`, `launchctl`,
  `security`, `sudo` or a shell, and never passes a hint's text to anything that runs it. The `yard`
  CLI is run with an argument vector and `--json`.
- Bundle id `dev.more.yard.app`; `LSUIElement` true; no App Sandbox; arm64 only.
- Protocol `"2.11"` (`yard_proto::PROTOCOL_VERSION`); `hello.client` is `Yard.app <version>
  (<YARD_BUILD_COMMIT>)`.
- Call timeout 60 s. Reconnect after 0.25 s, 0.5 s, 1 s, 2 s, then every 5 s.
- Socket paths at most 104 bytes; test sockets under `/tmp/yard-test-<random>`.
- Client-made errors use the CLI's words (one copy, in `yard-client`): `yardd is not running`
  (`DAEMON_NOT_RUNNING`, hint `yard start`); `lost the connection to yardd: <e>` and `yardd closed
  the connection` (`INTERNAL`, hint `yard doctor checks why`); `yardd did not answer <method> within
  60 s` (`INTERNAL`, hint `yard doctor checks what is stuck`); `yardd answered <method> in an
  unexpected shape: <e>` (`PROTOCOL_MISMATCH`, hint `upgrade yard and yardd together`); `yardd
  speaks protocol <p> and has no <method>` (`METHOD_NOT_FOUND`, hint `yard stop && yard start`).
- Every interactive GPUI element has an id that is stable across frames, a role and a label
  (design §8.5).
- Tests never touch `~/.yard`, the real LaunchAgent, Herd, `/etc/resolver` or a real port, and
  never run a real `yard start`, `stop`, `trust` or `helper`.
- Disk: at the end of a session that built, `cargo clean --profile dev` at the root and remove
  `app/target` (a GPUI build is several GB); never `target/release` at the root (the LaunchAgent
  runs it). Report what was removed.
- Work on main. Commit messages: a lowercase prose subject, prose paragraphs, no type prefix, no
  trailers. Ask the maintainer before each commit.

## Review Focus

The six failure modes most likely to bite a person using the app, each pinned by a test in the
task named:

1. **yardd restarts while a job runs, and the next job reuses its id** (`php-install-1` again):
   the old job shows lost, the new one is a separate record (Task 8,
   `a_reused_id_after_reconnect_is_a_new_job`).
2. **A job fails before its call answers** (a refused install finishes in microseconds): one
   record, and `run_job` still returns the failure (Task 10, `finished_before_the_answer_returns`).
3. **yardd was not restarted after a build** (it speaks 2.10, the app 2.11): `subscribe` leaves out
   `state`, so the subscription does not fail and events still arrive (Task 6,
   `stale_daemon_subscribes_without_state`).
4. **A newer yardd sends a value this build does not know** (an error code, a unit state): the
   answer still decodes (Task 1, `unknown_values_read_as_their_fallback`).
5. **A path or hint with a space, a quote or shell syntax**: a Terminal hand-off quotes every
   argument, and a hint like `rm -rf ~/x` or `yard service start "a b"` is only offered to copy
   (Task 9, `unknown_and_malformed_hints_only_copy`, `terminal_script_quotes_every_argument`).
6. **A large answer split across reads, and two events in one read** (a 300 KB site list):
   framing delivers each line whole and in order (Task 5, `lines_survive_any_chunking`).
