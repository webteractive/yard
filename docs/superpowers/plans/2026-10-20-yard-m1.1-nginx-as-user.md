# Yard M1.1 — nginx as the user — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** nginx runs as the user under `yardd`; root only hands over loopback 80/443 sockets, and only in the opt-in `privileged` profile.

**Architecture:** nginx becomes an ordinary supervised unit (foreground, `SIGHUP` reload, `nginx -t` run by `yardd`). The helper loses its four nginx verbs and gains `ports.bind`, which binds 80 or 443 on `127.0.0.1` and `::1` and returns the listening sockets over its unix socket (`SCM_RIGHTS`); `yardd` keeps them and passes them to nginx through nginx's `NGINX="fd;fd;"` inheritance. Profiles become `standard`/`privileged` and stop setting the TLD.

**Tech Stack:** Rust 1.92 (edition 2024), tokio, libc (`sendmsg`/`recvmsg`), socket2, brew nginx.

**Spec:** `docs/superpowers/specs/2026-10-19-yard-design.md` (revised 2026-10-20: §3.1, §5.2, §5.3, §5.5, §7, §12 M1.1).

## Global Constraints

- Rust 1.92, edition 2024. No new crates; socket2 is already in the workspace (yard-daemon), libc everywhere. `cargo deny check` after any `Cargo.lock` change.
- Tests never bind 53, 80, 443, 8080, 8443 or 53535; they take OS-assigned ports. The helper's privileged port list is injectable (`HelperConfig.privileged_ports`) for that reason.
- No `.unwrap()`/`.expect()` on daemon or helper runtime paths; errors are `YardError` with a hint.
- Every spawned child gets `fds::cloexec_inherited`; a unit's inherited sockets are made inheritable again *after* it, in the same `pre_exec` hook.
- Helper verbs take no paths or commands. `ports.bind` accepts only ports in `privileged_ports` (production: `[80, 443]`, `yard_proto::helper::PRIVILEGED_PORTS`).
- Profiles: `standard` (8080/8443, default) and `privileged` (80/443). `trial` and `default` in an existing `ports.toml` or on the CLI are read as `standard` and `privileged`. The TLD is `yard.toml`'s `tld`, else `yard` (`DEFAULT_TLD`).
- Herd keeps working: Yard never writes Herd's files, and `/etc/resolver/test` stays Herd's.
- Commits: lean prose, lowercase subject, no type prefix, no trailers, on main; never push. (M1 ran under the maintainer's "put all work in main and commit"; confirm it holds for M1.1 before Task 1's commit.)
- Docs move with the code: spec, README, AGENTS.md, `--help`, `.hydra/rules/`.

## Review Focus

1. **Upgrading from M1** with M1's root nginx still running on 8080 and `logs/nginx-error.log` and `run/nginx.pid` root-owned: `sudo yard helper install` must stop that nginx through the old helper and give both files back to the user, or the user nginx cannot start. (Executed as removal, not chown: see the Task 4 ruling in the ledger and commit 7dc2e4f; nginx recreates both files as the user.) Pinned by Task 4's `legacy_root_files_are_m1_nginx_outputs` and Task 7's real-machine run.
2. **`yard ports profile privileged` while Herd holds 80/443:** refused, Herd named as the holder, nothing changed. As the user, a loopback bind of 80 fails with "permission denied", so the probe must answer by connecting instead. Pinned by Task 6's `privileged_port_with_a_listener_is_busy` and Task 7's e2e step.
3. **`yard restart nginx` when the config cannot be tested** (nginx binary gone, test cannot run): refused, nginx untouched, no "Restarted nginx." This is the verification finding from 2026-10-20. Pinned by Task 3's `restart_nginx_refuses_when_the_config_cannot_be_tested`.
4. **yardd restarts in the privileged profile:** the new yardd asks the helper again and nginx comes back on 80/443. Pinned by Task 6's `privileged_sockets_are_rebound_after_a_yardd_restart`.
5. **Switching privileged → standard:** loopback 80/443 are closed, so Herd or anything else can take them again. Pinned by Task 6's `switching_to_standard_releases_the_privileged_sockets`.

### Task 1: Spike — nginx serves on inherited sockets as the user

The design depends on brew nginx (1) serving on a listening socket it inherits through `NGINX`, (2) keeping it across `SIGHUP`, and (3) passing `nginx -t` with it, all as a non-root master. Prove this before building on it.

**Files:**
- Create: `crates/yard-daemon/tests/real_nginx.rs`

**Interfaces:**
- Consumes: `support::free_port`, `yard_core::brew::Brew::new(Path::new("/opt/homebrew")).nginx_bin()`.
- Produces: nothing; the test stays as an opt-in check (`#[ignore = "needs brew nginx"]`), run with `cargo test -p yard-daemon --test real_nginx -- --ignored`.

- [ ] **Step 1: Write the test `real_nginx_serves_on_an_inherited_socket`**

The test binds `127.0.0.1:p` itself and *keeps its own copy open*, so nginx binding `p` on its own would fail with `EADDRINUSE`: serving proves inheritance. It clears `FD_CLOEXEC` on the listener's fd, writes a minimal config in a temp prefix (`daemon off; master_process on; pid <tmp>/nginx.pid; error_log <tmp>/error.log;` and one server with `listen 127.0.0.1:<p>; return 200 "inherited";`), and spawns `nginx -p <tmp>/ -c <tmp>/nginx.conf -e <tmp>/error.log` with `NGINX="<fd>;"`. Assertions:

```rust
assert_eq!(get(p), "inherited");                 // (1) serves
kill(nginx_pid, SIGHUP); sleep(500 ms);
assert_eq!(get(p), "inherited");                 // (2) survives a reload
let t = Command::new(&bin).args(["-t", "-p", .., "-c", .., "-e", ..]).env("NGINX", format!("{fd};")).status();
assert!(t.success());                            // (3) -t passes with the inherited fd
```

`get(p)` is a raw `GET / HTTP/1.0` over `TcpStream` returning the body. Kill nginx (`SIGTERM`) at the end.

- [ ] **Step 2: Run it**

Run: `cargo test -p yard-daemon --test real_nginx -- --ignored --nocapture`
Expected: PASS. Also record whether `nginx -t` *without* `NGINX` fails here with "Address already in use"; that tells Task 6 whether `-t` needs the sockets (it gets them either way).

If (1) or (2) fails, stop and ask the maintainer. That is the "plan so broken" stop. The fallback is the helper spawning nginx as the user with the sockets, a different Task 5/6.
