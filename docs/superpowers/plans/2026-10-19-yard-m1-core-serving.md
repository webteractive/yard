# Yard M1 — Core serving Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CLI-only Yard that serves parked, linked and proxied sites over
`http://<site>.yard:8080` on one PHP version, side by side with a running Herd.

**Architecture:** A Cargo workspace. `yard-core` holds all pure logic: config,
port registry, site resolution, rendering, write planning and restart policy.
`yard-daemon` holds every side effect and runs as `yardd`, a user LaunchAgent
that supervises dnsmasq and php-fpm and talks JSON-RPC over a unix socket.
`yard-helper` is a root LaunchDaemon with a fixed verb set for nginx and
`/etc/resolver`. `yard-cli` is a thin client. Every unit is reconciled from
the three TOML files.

**Tech Stack:** Rust 1.92 (edition 2024), tokio, serde, serde_json, toml,
toml_edit, clap 4 (derive), thiserror, tracing, notify + notify-debouncer-mini,
socket2, libproc, nix, plist, sha2. Dev-only: insta, tempfile, assert_cmd.
Homebrew supplies nginx, dnsmasq and `shivammathur/php/php@<ver>`.

**Spec:** `docs/superpowers/specs/2026-10-19-yard-design.md` (§3, §5.1–5.3,
§5.5 trial profile, §6, §7 and §10 for M1). Read it before starting any task.
`AGENTS.md` and `.hydra/rules/` hold the conventions that come out of this plan.

## Global Constraints

- macOS 14+, arm64 only. `rust-toolchain.toml` pins `1.92`; edition `2024`.
- Homebrew prefix default `/opt/homebrew`. Never run `brew services`; never write a file under the brew prefix.
- Data root `~/Library/Application Support/Yard/`, overridable by `YARD_ROOT` env or `--root` (tests always override). The path contains a space: every rendered path is quoted.
- Trial profile is the default: TLD `yard`, `nginx-http` 8080, `nginx-https` 8443. Default profile: TLD `test`, 80/443. `dnsmasq` is pinned at 53535 in both. `range = "33000-33999"`, `auto_fallback = false`.
- Every generated file starts with `# Generated by Yard — edit <overrides path> instead` (`<!-- … -->` for HTML). Files marked USER-OWNED in spec §3.3 are created empty once and never rewritten.
- FPM: `pm = ondemand`, `pm.max_children = 10`, `pm.process_idle_timeout = 30s`, socket `run/php-<ver>.sock`.
- Supervisor: health every 5 s; backoff 1 s doubling to 30 s; 5 failures in 60 s → `failed`, keep the last 50 log lines; logs rotate at 10 MB, keep 5.
- FSEvents debounce 500 ms; foreign-listener port scan every 30 s.
- Labels `dev.more.yard.daemon` and `dev.more.yard.helper`; helper socket `/var/run/dev.more.yard.helper.sock`; helper binary `/Library/PrivilegedHelperTools/dev.more.yard.helper`.
- Errors are `{ code, message, hint, data? }` with stable SCREAMING_SNAKE codes (spec §6.3).
- CLI exit codes: 0 success, 1 Yard error, 2 usage error, 3 `yardd is not running → yard start`.
- Tests never bind 53, 80, 443, 8080, 8443 or 53535. They ask the OS for a free port (bind port 0) and use a temp `YARD_ROOT`.
- No `.unwrap()`/`.expect()` on daemon or helper runtime paths; tests may.
- Run `cargo deny check` after every `Cargo.lock` change. Vet each new crate as the global rust-dependencies rule describes.
- Commit steps mean: show the diff summary, **ask the maintainer**, then commit. Messages are lean prose, no type prefix, no trailers.

## Review Focus

1. **Paths with spaces.** The data root is `…/Application Support/Yard`, and site directories can contain spaces. Every path in nginx, php-fpm, php.ini, dnsmasq and plist output must survive that. Tests: Task 7 `renders_paths_with_spaces_quoted`, Task 13 `serves_site_in_dir_with_space`.
2. **Herd's state is off limits.** `/etc/resolver/test` belongs to Herd, and Herd's nginx holds 127.0.0.1:80/443. A profile switch while Herd holds the ports must be refused with Herd named as the holder, and a resolver file without Yard's marker is never written or removed. Tests: Task 4 `profile_switch_reports_holders`, Task 11 `resolver_refuses_foreign_file`, Task 10 `classifies_herd_holder`.
3. **A hand-edited TOML with a typo.** The daemon keeps serving the last good state, reports `CONFIG_INVALID` with file, line and column, and never wipes generated configs. Tests: Task 3 `config_error_has_location`, Task 13 `bad_toml_keeps_last_good_state`.
4. **A broken `nginx/overrides/<site>.conf` or a hand-edited generated file.** `nginx -t` failure restores the previous config set and names the file; a hand edit is backed up, never silently lost. Tests: Task 8 `hand_edit_is_backed_up_when_render_changes`, Task 13 `nginx_test_failure_restores_previous_configs`.
5. **Odd directory names in a parked path.** Uppercase, spaces, underscores, dots, hidden directories, plain files and broken symlinks are normalized or skipped with a warning, and never produce an invalid `server_name`. Test: Task 5 `normalizes_and_skips_odd_entries`.

### Task 4: `yard-core` — port registry

**Files:**
- Create: `crates/yard-core/src/ports/mod.rs`, `crates/yard-core/src/ports/holder.rs`
- Test: unit tests in both

**Interfaces:**
- Consumes: `Paths`, `TomlFile`, `yard_proto::{Profile, PortMode, YardError, HolderKind, Holder}`.
- Produces:
  - `struct PortRange { start: u16, end: u16 }` with `FromStr` for `"33000-33999"`; inclusive; rejects `start > end` and `start < 1024`.
  - `struct PortEntry { port: u16, mode: PortMode, preferred: Option<u16> }`.
  - `struct Registry { range: PortRange, auto_fallback: bool, profile: Profile, entries: BTreeMap<String, PortEntry> }`.
  - `Registry::load(paths) -> Result<Registry, YardError>`. When `ports.toml` is missing it seeds: the spec §7 header values, `nginx-http`/`nginx-https` pinned from `profile`, and `dnsmasq` pinned 53535. Pinned ports outside `range` are fine; `auto` entries must be inside it.
  - `fn validate(&self) -> Vec<String>`: duplicate ports across entries (an `external` duplicating anything counts), `preferred` mode without `preferred`, `auto` outside the range.
  - `fn allocate(&mut self, unit: &str, mode: PortMode, preferred: Option<u16>, is_free: &dyn Fn(u16) -> bool) -> Result<u16, YardError>`. Semantics per spec §7 Modes. `auto` takes the lowest port in range not held by another entry and free per `is_free`. For `preferred` with `auto_fallback = false`, an unusable preferred port is `PORT_IN_USE` with hint `yard ports set <unit> <port>` or `set auto_fallback = true in ports.toml`. For `pinned`, a port held by another entry is `PORT_CONFLICT` and an unavailable one is `PORT_IN_USE`.
  - `fn ensure(&mut self, unit, mode, preferred, is_free) -> Result<u16, YardError>` returns the existing entry when present. For `preferred` it retries the preferred port first and records the result.
  - Mutators returning `Result<(), YardError>`: `set(unit, port)` (fails `PORT_CONFLICT` when another entry holds the port), `pin(unit)`, `unpin(unit)` (pinned→preferred with `preferred = port`), `set_range(PortRange)`, `set_profile(Profile, is_free) -> Result<(), YardError>`. `set_profile` checks both of the new profile's ports first and returns one `PORT_IN_USE` naming every unavailable port in `data.ports` before changing anything.
  - `fn save(&self, file: &mut TomlFile)` writes entries as inline tables in the spec §7 shape.
  - `holder.rs`: `fn classify(name: &str, path: Option<&str>, ppid: Option<u32>, launchd_label: Option<&str>) -> HolderKind`. Rules, in order: a path containing `/Herd.app/` or `/Library/Application Support/Herd/` → `Herd`; label starting with `homebrew.mxcl.` or a path under the brew prefix with `ppid == Some(1)` → `BrewServices`; name or path containing `com.docker` or `vpnkit` → `Docker`; a path inside a `Yard.app` bundle or ending in `/yardd` → `Yard`; otherwise `Unknown`.

    5. Every state change emits `UnitStateChanged`.
    6. Child stdout and stderr both go to the unit's `LogSink`.

### Task 13: `yard-daemon` — state and reconcile

**Files:**
- Create: `crates/yard-daemon/src/{state.rs,reconcile.rs}`
- Test: `crates/yard-daemon/tests/reconcile.rs`

**Interfaces:**
- Consumes: everything in `yard-core`, `Supervisor`, `HelperClient`, `probe`, `EventBus`.
- Produces:
  - `struct Snapshot { yard: YardConfig, sites_cfg: SitesConfig, registry: Registry, tld: String, resolution: Resolution }` (the last good state).
  - `struct State { paths, brew, snapshot: Option<Snapshot>, config_error: Option<YardError>, applied_resolver: Option<(String, u16)>, hashes: Hashes }`.
  - `struct Reconciler { state: tokio::sync::Mutex<State>, supervisor, helper, bus }` with `async fn reconcile(&self) -> Result<ReconcileReport, YardError>` and `struct ReconcileReport { written: Vec<PathBuf>, removed: Vec<PathBuf>, hand_edited: Vec<PathBuf>, warnings: Vec<String> }`. Calls are serialized by the mutex.
  - The algorithm. Each step either completes or returns an error with the previous state intact:
    1. **Load config.** Load the three TOMLs. On error, set `config_error`, keep `snapshot` and running units untouched, and return `CONFIG_INVALID`.
    2. **Settle ports.** Effective tld = `yard.tld` or `registry.profile.tld()`. `ensure` `nginx-http` and `nginx-https` (pinned to the profile) and `dnsmasq` (pinned 53535), plus an `external` entry `proxy:<name>` for every proxy site. A unit's own currently running port counts as free for itself. Save `ports.toml` only if it changed.
    3. **Resolve sites.** List the parked dirs (follow symlinks; a missing parked path is a warning) and run `sites::resolve`.
    4. **Render.** Render every generated file and `ensure_user_file` each site override, plus `php/<v>/conf.d/99-overrides.ini` with the header comment `; USER-OWNED — Yard never rewrites this file`.
    5. **Write.** Plan and apply the writes.
    6. **Test nginx.** If any file under `nginx/` changed, call `helper.test_nginx()`. When `ok == false`, roll back and return `NGINX_CONFIG_INVALID` with `data.output`.
    7. **Apply units.** The desired units are `dnsmasq` (always), `nginx` (always) and `php-fpm-<default>` (only when at least one PHP site exists). Units whose generated files changed are restarted; nginx is reloaded instead. If the helper is unreachable, nginx is left `Failed` with `HELPER_NOT_INSTALLED` and the other units still run.
    8. **Resolver.** If `(tld, dnsmasq port)` differs from `applied_resolver`, install the new resolver and remove the old TLD's.
    9. **Commit.** Store the snapshot, clear `config_error`, and emit `SiteAdded`/`SiteRemoved` for name diffs.

### Task 14: `yard-daemon` — RPC server, watchers, port scan, `yardd`

**Files:**
- Create: `crates/yard-daemon/src/{rpc/mod.rs,rpc/server.rs,rpc/handlers.rs,watch.rs,portscan.rs,daemon.rs,bin/yardd.rs}`
- Test: `crates/yard-daemon/tests/rpc.rs`

**Interfaces:**
- Consumes: `Reconciler`, `Supervisor`, `EventBus`, `TomlFile`, `Registry`, `probe`, `holder`, the `yard_proto::methods` consts.
- Produces:
  - `struct DaemonOptions { paths: Paths, brew_prefix: PathBuf, helper_socket: PathBuf, supervisor: SupervisorConfig, debounce: Duration, port_scan_interval: Duration }`.
  - `async fn run(opts: DaemonOptions, shutdown: impl Future) -> Result<(), YardError>`. If the socket file exists and accepts a connection, it returns `Internal` ("yardd is already running"). If the file exists but refuses, it is removed as stale. A socket path over 103 bytes is `INVALID_ARGUMENT` naming the path. It binds `daemon_socket` with mode 0600, runs the first reconcile (an error is logged and kept in state; the daemon still serves), starts the watchers and the port scan, and serves until shutdown. Shutdown calls `supervisor.shutdown()` and stops nginx through the helper, then removes the socket.
  - Connection protocol: the first request must be `hello`. A different major version in `params.protocol` is `PROTOCOL_MISMATCH` with hint `upgrade yard and yardd together (yardd <ver>)`, after which the connection closes. Requests on one connection are handled in order. After `subscribe` the connection also receives `Notification`s for the requested topics. A subscriber that lags skips the events it missed, and the daemon logs how many.
  - Handlers. Each mutation edits a TOML via `TomlFile`, then awaits `reconcile`, and returns the affected `SiteInfo` / `PortInfo` / `()`:
    - `sites.link`, `unlink`, `proxy`, `unproxy` and `docroot` edit `sites.toml`. `link` canonicalizes `path` and requires it to be a directory. The name defaults in the CLI, not here. `unlink`/`unproxy` of an unknown name is `SITE_NOT_FOUND`.
    - `park` and `unpark` edit `yard.toml`.
    - `ports.*` mutate the `Registry` and save it.
    - `ports.check` → `Vec<PortInfo>`. Status is `Yard` when the owning unit is `Running`; otherwise it comes from `is_free` / `find_holder`. External entries are checked with `is_listening`.
    - `units.restart` takes `UnitParams`.
    - `status`, `sites.list`, `ports.list` and `doctor` (Task 15) read state.
  - `watch.rs` uses `notify-debouncer-mini` at `debounce` on each parked path (non-recursive) and on the three TOML files. Any event triggers `reconcile`. The watch set is rebuilt after each reconcile when `parked` changes.
  - `portscan.rs`: every `port_scan_interval`, each non-external entry whose unit is not `Running` is probed. When a port goes free → held, it emits `PortConflict { unit, port, holder }`, once per transition.
  - `bin/yardd.rs`: parses `--root`, builds `DaemonOptions` with production defaults (helper socket `HELPER_SOCKET`, brew from `Brew::detect`), installs a tracing subscriber writing to stderr (launchd sends it to `logs/yardd.log`), and maps SIGTERM/SIGINT to shutdown.
