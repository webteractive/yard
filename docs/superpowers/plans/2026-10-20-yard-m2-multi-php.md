# Yard M2 — Multi-PHP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sites are explicit links only, and each one runs on the PHP version it is isolated to. Yard installs and removes PHP versions and extensions through brew, owns every ini PHP loads, and a `php` shim on PATH picks the right version per directory.

**Architecture:** Parking goes, along with its watcher, its RPC methods and `SiteSource::Parked`. Since that removes methods and a variant, the protocol moves to 2.0. Long brew operations become **jobs**: the method returns a `job_id` at once, and `job.progress` and `job.finished` events stream on a new `jobs` topic. PHP's ini scan dir becomes Yard's `conf.d` only. Reconcile mirrors brew's `conf.d` inis into it as generated `10-brew-*.ini` files and renders `50-<ext>.ini` for each extension Yard manages, so `ext disable` works whatever installed the extension. Extension state and per-site isolation live in the user TOMLs and change only through `TomlFile` and then reconcile. A new `yard-shim` crate is the multicall `php`/`composer`/`pecl`/`phpize`/`php-config` binary; it reads the TOMLs directly and `exec`s brew's binary.

**Tech Stack:** Rust 1.92 (edition 2024), tokio, toml/toml_edit, serde_json, clap, brew (`shivammathur/php`, `shivammathur/extensions`).

**Spec:** `docs/superpowers/specs/2026-10-19-yard-design.md`: §3.3, §4 (all), §5.1, §6.2, §6.3, §10, §12 M2.

## Global Constraints

- Rust 1.92, edition 2024. No new third-party crates. `yard-shim` is a new workspace crate that depends on `yard-core` and `yard-proto` only. Run `cargo deny check` after the `Cargo.lock` change.
- Supported PHP: 7.0–8.5 (`yard_core::php::SUPPORTED`). Formulas: `shivammathur/php/php@<v>` (8.5's `php@8.5` alias included); extension formulas `shivammathur/extensions/<name>@<v>`.
- **Never Herd's PHP** (maintainer, 2026-10-20). On this machine `~/Library/Application Support/Herd/bin` comes before `/opt/homebrew/bin` on PATH, so a bare `php` or `composer` is Herd's. Yard never runs php, composer, pecl, phpize or php-config by name. It uses the absolute brew paths (`opt/php@<v>/bin/<name>`, `<prefix>/bin/composer`). Every child Yard starts (jobs, `php -m` verification, shim `exec`) gets `PATH` from `yard_core::shim::child_path`: the resolved version's `opt/php@<v>/bin` first, then the rest of PATH with every entry containing `/Herd/` removed. That stops pecl's `phpize`, and composer scripts that call `php`, from reaching Herd.
- Never `brew services`; never write under the brew prefix. Yard *reads* brew's `etc/php/<v>/conf.d`. `brew install`/`uninstall` run only inside a `yard` command the user invoked. Tests use a fake `brew` and never the real one.
- Tests never bind 53, 80, 443, 8080, 8443 or 53535, and never run real brew, pecl or php.
- No `.unwrap()`/`.expect()` on daemon, helper or shim runtime paths. Errors are `YardError` with the exact fixing command as `hint`.
- New stable error codes (never renamed): `EXT_VERIFY_FAILED`, `EXT_NOT_FOUND`, `PHP_IN_USE`, `JOB_FAILED`.
- `PROTOCOL_VERSION` becomes `"2.0"` in Task 1 (methods and `SiteSource::Parked` removed); later tasks are additive and leave it.
- Generated files carry the `# Generated by Yard` / `; Generated by Yard` header and a stored hash; `99-overrides.ini` stays user-owned and is written only by `yard php config set|unset`.
- Herd keeps working: Yard never writes Herd's files, never creates directories in `~/Herd`, and `/etc/resolver/test` stays Herd's.
- Commits on main, lean prose, lowercase subject, no type prefix, no trailers; never push (there is no remote). the maintainer's "commit everything" from 2026-10-20 covers each task's commit.
- Docs move with the code in the same task: spec, README, AGENTS.md, `--help`, `.hydra/rules/`.

## Review Focus

1. **Upgrading with M1's `yard.toml`**, which may still have `parked = [...]`: yardd must keep serving. The key is read and ignored with a warning naming the file, never `CONFIG_INVALID`. Pinned by Task 1's `parked_key_is_ignored_with_a_warning`.
2. **Brew's own extension inis after the scan-dir change.** On the maintainer's machine `etc/php/8.4/conf.d` loads OPcache, and 7.4 has phpredis. Dropping brew's dir from `PHP_INI_SCAN_DIR` must not drop them. Pinned by Task 6's `brew_conf_d_inis_are_mirrored_except_managed` and Task 10's real-machine `php -m` check for `Zend OPcache`.
3. **`yard ext add` where every source fails** (no brew formula, pecl fails): the job finishes with `JOB_FAILED` and `yard.toml` is byte-for-byte unchanged. Pinned by Task 7's `ext_add_with_no_source_leaves_yard_toml_unchanged`.
4. **Removing what is in use:** `yard php uninstall` of the default version, or of a version a site is isolated to, is refused with `PHP_IN_USE`, names the sites, and runs no brew. Pinned by Task 3's `uninstall_refuses_default_and_isolated_versions`.
5. **Herd's PHP sneaking in through PATH**: `pecl install` calls `phpize`/`php-config` by name, and composer scripts call `php` by name. On this machine either would find Herd's first. Every child Yard starts must get `child_path`, and `yard install-shims` must warn while `php` on the user's PATH is not Yard's shim. Pinned by Task 2's `job_path_puts_the_keg_first_and_drops_herd`, Task 9's `child_path_drops_herd_entries` / `shim_child_path_reaches_brew_not_herd` / `install_shims_warns_when_herd_php_comes_first`, and Task 10's e2e `PHP_BINARY` and php-fpm binary checks.

  - `types::JobStarted { job_id: String }`, the result of every job method.
  - `jobs::Jobs::new(bus: EventBus) -> Jobs`, and `Jobs::start<F>(&self, kind: &str, work: F) -> JobStarted` where `F: FnOnce(JobCtx) -> BoxFuture<'static, Result<(), YardError>> + Send + 'static`. Jobs run one at a time, in start order (brew holds a global lock anyway). Ids are `"<kind>-<n>"`.

It subscribes to `jobs` before calling, prints each progress line for its `job_id` (human) or each event as NDJSON (`--json`), and exits per `JobFinished`.

### Task 6: Yard owns every ini PHP loads

This is the groundwork for extensions. It changes no commands.

**Files:**
- Modify: `crates/yard-core/src/config/yard.rs` (`extensions`), `crates/yard-core/src/render/php.rs` (`php_fpm_env`, `brew_inis`, `ext_ini`), `crates/yard-core/src/render/mod.rs` (`overrides_for` for the new files), `crates/yard-daemon/src/reconcile.rs` (render for every installed version, read brew's conf.d), `.hydra/rules/homebrew.md` (the scan dir, and the known M2 issue resolved), spec §3.3, §4.1 and §4.3
- Test: `crates/yard-core/src/{config/yard.rs,render/php.rs}` (insta snapshots), `crates/yard-daemon/tests/reconcile.rs`

**Interfaces:**
- Produces:
  - `config::yard::ExtEntry { source: ExtSource, enabled: bool /* default true */, so: Option<PathBuf> }` and `ExtSource { Brew, Pecl, Path, Bundled }`, with serde names `brew`/`pecl`/`path`/`bundled`. In `yard.toml`:
    ```toml
    [php."8.4".extensions]
    redis = { source = "brew" }
    opcache = { source = "bundled", enabled = false }
    ```
    `source = "path"` requires `so` (absolute). A missing `so`, an unsupported version key, or an unknown source is `CONFIG_INVALID`.
  - `render::php::brew_inis(files: &[(String, String)], exts: &BTreeMap<String, ExtEntry>) -> BTreeMap<String, String>`. It maps each brew `conf.d` file `<f>.ini` to Yard file name `10-brew-<f>.ini` with the generated header plus the original text. It skips a file when an `extension=` or `zend_extension=` line in it loads an extension that `exts` manages, or one marked `bundled` and disabled.
