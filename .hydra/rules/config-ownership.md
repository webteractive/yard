# Config ownership

Herd overwriting user config is one of the pain points Yard exists to fix. Keep it fixed.

- **Three kinds of file.**
  - Generated files start with `# Generated by Yard — edit <overrides path> instead`
    (`<!-- … -->` in HTML) and have their sha256 recorded in `state/hashes.json`.
  - User-owned files (`nginx/overrides/<site>.conf`, `php/<v>/conf.d/99-overrides.ini`)
    are created empty once with `ensure_user_file` and never written again, except
    `99-overrides.ini` through `yard php config set|unset` (`rpc/php.rs`
    `config_edit`, via `yard_core::ini`, which keeps every other line as written).
  - User TOMLs (`yard.toml`, `sites.toml`, `ports.toml`) are edited only through
    `config::edit::TomlFile` (`toml_edit`), so comments and key order survive.
- **Write rule** (`generated::plan`): compare against the stored hash, not just the
  render. A hand-edited file whose render did not change is left alone and reported by
  `yard doctor`, which names the override from `render::overrides_for` (a test keeps it
  in step with each file's header). A hand-edited file whose render changed is copied to
  `<file>.yard-backup` before it is written. A file with no stored hash is never deleted.
- Every config change that touches `nginx/` runs `nginx -t` from yardd, as the user
  (`nginx::NginxCommand::test`). On failure, roll back the whole write set and return
  `NGINX_CONFIG_INVALID` with nginx's output. An nginx that cannot run at all is a
  warning on reconcile and a refusal on `yard restart nginx`.
- User overrides are applied too: the watcher sees `nginx/overrides/` and calls
  `Reconciler::apply_overrides`, which runs `nginx -t` and reloads only if it passes.
  `yard restart nginx` tests first and refuses a broken config, so a typo in an
  override never takes sites down.
- A TOML parse error never takes sites down. Keep the last good snapshot and report
  `CONFIG_INVALID` with file, line and column. Values that would break a render are
  parse errors too (`tld` against `valid_tld`, two units on one port), located at
  their span. Every failed reconcile is kept in `State.last_error`, which `status`
  and `doctor` report until a reconcile succeeds.
- **Quote every path** in rendered output. The data root is
  `~/Library/Application Support/Yard`, and that space breaks unquoted nginx, fpm and ini values.
- Yard never writes project `.env` files (spec non-goal).
